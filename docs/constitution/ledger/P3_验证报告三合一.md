## 三、DependencyGuard 运行时实测方案（待部署后执行）

### 测试环境要求

| 项目 | 值 |
|------|---|
| 部署版本 | 1af7613 |
| 中间件 | src/server/middleware/dependencyGuard.js |
| 注册位置 | src/server/index.js: app.use('/api', dependencyGuard) |

### 测试用例 1：直连模型接口拦截

```
请求: GET /api/ai/chat
请求头: X-Caller-Module: vocabulary
预期: HTTP 403
响应体: { "code": 9001, "violation": "DIRECT_AI_CALL_FORBIDDEN" }
服务端日志: [DependencyGuard] DIRECT_AI_CALL
判定标准: 返回码 403 + code 9001 = 通过
```

### 测试用例 2：跨模块调用拦截

```
请求: GET /api/billing/status
请求头: X-Caller-Module: vocabulary
预期: HTTP 403
响应体: { "code": 9001, "violation": "CROSS_DOMAIN_CALL" }
判定标准: 返回码 403 + code 9001 = 通过
```

### 测试用例 3：Redis 直写拦截

```
请求: GET /api/user/profile
请求头: X-Redis-Write: true, X-Caller-File: src/server/controllers/userController.js
预期: HTTP 403
响应体: { "code": 9001, "violation": "DIRECT_REDIS_WRITE" }
判定标准: 返回码 403 + code 9001 = 通过
```

### 不满足标准时的处置

任意一类测试返回码不是 403 或 code 不是 9001，判定整改不通过，需排查中间件注册、路由匹配、异常捕获逻辑。
