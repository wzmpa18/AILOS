# 增补 7：图谱-代码版本强制绑定机制

> 文档性质：P0 必补项，彻底杜绝"图纸和代码两张皮"的治理失效风险
> 关联宪法：CoreOS 第 0 编四大铁律、Z1.3 图谱外即非法、Z1.4 整改终身追踪
> 图谱版本：v3.0.0（当前正式版本，与宪法 v3.0 一一对应）

---

## 7.1 版本号规则

| 要素 | 规则 |
|------|------|
| **图谱版本号** | `v<MAJOR>.<MINOR>.<PATCH>`，当前 v3.0.0 |
| **宪法版本号** | 与图谱 MAJOR.MINOR 同步，当前 v3.0 |
| **代码仓库版本** | 与图谱版本绑定，通过 Commit Message 标注 |
| **MAJOR 升级** | 五层内核架构变更、领域模块新增/删除 |
| **MINOR 升级** | 单模块依赖变更、路由新增/删除、数据表结构变更 |
| **PATCH 升级** | 文案修正、格式调整、注释补充（不涉及架构） |

## 7.2 代码提交强制绑定规则

### 7.2.1 Commit Message 格式

```
<type>(<scope>): <subject> [图谱版本:v3.0.0]

type: feat/fix/refactor/docs/chore
scope: 对应领域模块（vocabulary/grammar/reading/brain/coreos等）
subject: 变更简述
[图谱版本:vX.Y.Z]: 必填，标注当前对应的图谱版本
```

**示例**：
```
feat(vocabulary): 新增N4词汇表 [图谱版本:v3.0.0]
fix(brain): 修复aiService直连混元路径 [图谱版本:v3.0.0]
refactor(coreos): EventBus骨架落地 [图谱版本:v3.0.1]
```

### 7.2.2 CI 拦截规则

| 检查项 | 违规处置 |
|--------|---------|
| Commit Message 无 `[图谱版本:vX.Y.Z]` 标注 | ❌ 禁止合并 |
| 版本号格式不匹配 `v\d+\.\d+\.\d+` | ❌ 禁止合并 |
| 版本号低于当前图谱最新版本 | ⚠️ 告警（允许合并但记录） |
| 新增路由/数据表/服务但图谱未更新 | ❌ 禁止合并 |

### 7.2.3 PR 强制检查清单

- [ ] Commit Message 包含 `[图谱版本:vX.Y.Z]`
- [ ] 若涉及架构变更，对应图谱文件已同步更新
- [ ] 若新增接口/服务/数据表，已在对应附录中登记
- [ ] 若修改依赖关系，附录 B 黑白名单已同步更新
- [ ] 若涉及 AI 调用路径变更，附录 F Brain 流程图已同步更新

## 7.3 图谱变更审批流程

```
开发提交图谱修改 PR → 架构师 Review → 总工程师 Approve → 合并 → 版本号升级 → 发布图谱变更公告
```

**规则**：
- 图谱文件的 PR 必须总工程师审批，任何人无权自行合并
- 图谱版本号升级后，所有后续代码提交必须使用新版本号
- 图谱变更公告发送至项目全体成员，公告内容包括：变更内容、影响范围、生效时间

## 7.4 图谱仓库保护规则

| 保护项 | 规则 |
|--------|------|
| **仓库归属** | `AILOS_指令中心/系统图谱/` 纳入 Git 主仓库 `_ailos_local_repo` |
| **分支保护** | `main` 分支设保护，禁止 force push |
| **CODEOWNERS** | 图谱文件设 CODEOWNERS = 总工程师 |
| **审批要求** | 图谱 PR 至少 1 人 Approve（架构师）+ 总工程师最终审批 |
| **只读归档** | 已 Frozen 的图谱版本打 Git Tag，不可修改 |

## 7.5 图谱与代码不一致时的处置

| 场景 | 处置 |
|------|------|
| 代码中有图谱未登记的路由/服务/表 | 判定 Z1.3 图谱外即非法 → 🔴 一级违宪 → 立即回滚或补登记 |
| 图谱中有但代码中已删除的接口 | 图谱标记 `[已废弃]`，版本号 PATCH +1 |
| 代码修改了调用路径但图谱未更新 | PR 驳回，要求同步更新图谱 |
