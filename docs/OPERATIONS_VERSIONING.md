# AILOS 运营迭代与版本治理规范

## 1. 日常运营迭代（零发版）
- 页面修改、内容更新、活动上线、规则调整一律在服务端修改
- 用户刷新页面即生效，无需更新安装包
- 示例：修改套餐价格 → 更新MembershipPlan表 → 前端刷新即生效

## 2. 版本兼容规则
- 服务端接口向下兼容至少2个历史版本
- 低版本APK不强制升级也可使用基础功能
- API版本路由：/api/v1/ (当前) + /api/v0/ (历史兼容)

## 3. 灰度发布机制
- 服务端支持按用户ID、按版本号灰度新功能
- 灰度配置存储在SystemConfig表
- 小范围验证后全量上线

## 4. 强制升级机制
- 服务端配置最低可用版本（SystemConfig: min_app_version）
- 低版本用户启动时弹窗提示升级
- 重大安全修复可触发强制升级

## 5. 版本台账
每次发版登记入账簿第62章：
- 版本号（versionName + versionCode）
- 对应Git基线commit
- 更新内容摘要
- 发布时间
- 灰度范围（全量/灰度百分比）

## 6. 回滚机制
- Git基线可追溯：每个APK对应唯一commit
- 服务端可快速回滚：git revert + pm2 restart
- APK回滚：重新构建历史版本包
