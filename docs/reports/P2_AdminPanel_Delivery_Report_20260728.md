## 一、交付背景

P2「基础运营管理后台」旨在为运营人员提供可浏览器访问的可视化 Web 管理页（非仅接口），覆盖订单查询导出、用户时长管理、异常订单标记三大模块，并满足权限隔离（普通用户 403）与登录 Session 并发冲突修复。交付后据治理指令补强 P1 六项生产必备能力，并完成文档/证据/清理全闭环。本报告作为总账第 37 章的过程支撑材料，与总账核心信息一一对应、版本一致。

## 二、需求基线

- 可视化 Web 管理页（正式路径 `https://yandao.vip/xuewaiyu/admin.html`）。
- 三大模块：订单查询与导出 / 用户时长管理（含管理员调整池）/ 异常订单标记。
- 权限隔离：普通用户访问 `/api/admin/*` 返回 403。
- Session 并发：同账号并发登录无 P2002、token 互异。
- P1 六项补强：分页 / 审计详情 / 路由守卫 / 操作密码 / 登录审计 / 账号管控。

## 四、故障复盘

**现象**：首轮部署后 P1-5/P1-6 运行时 500；`prisma migrate status` 显示 `20260728000000_p1_admin_reinforce` 仍为 pending；`LoginLog` 表与 `User.disabled` 列不存在（`P1014`）。

**根因**：`deploy.sh` 的 `migrate deploy` 步骤无中断机制（`set -uo pipefail` 无 `set -e`，失败不中断）；健康闸门 GATE1/GATE2 不校验 schema 版本，缺陷被放行。

**修复**：服务器直接 `prisma migrate deploy` 补应用该迁移（幂等，未新增文件）；复检 `Database schema is up to date!`。详见总账 §37.3。

## 五、P1 补强明细

- **P1-1 分页**：订单/用户/操作日志/登录审计四类列表默认 20/页，最大 100，返回 `{count,total,page,pageSize,data}`。
- **P1-2 审计详情**：`AdminOperationLog` 落库 before/after，前端可展开查看变更详情。
- **P1-3 路由守卫**：`admin.html` 未登录重定向登录页；失效自动跳转；后端 `authenticate, requireAdmin` 双守卫。
- **P1-4 操作密码**：敏感操作（时长调整/异常标记/账号管控）后端 `verifyOpPassword` 校验（默认 `Admin@2026`），错误 403。
- **P1-5 登录审计**：`LoginLog` 表记录时间/IP/设备（userAgent），`GET /api/admin/login-logs` 可查。
- **P1-6 账号管控**：`User.disabled` 状态位 + `resetPassword`；禁用后登录返回 401，全程留痕。
