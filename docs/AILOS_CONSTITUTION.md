## Chapter 5: ADR 架构变更规则

### 变更触发条件

以下操作必须发起 ADR 审批：

| 操作 | 触发条件 |
|------|---------|
| 修改 Frozen Module | 任何对冻结模块的改动 |
| 新增数据表 | 需明确业务必要性、兼容方案 |
| 修改数据表结构 | 字段增删改、关系变更 |
| API 路由变更 | 路径、方法、中间件栈变更 |
| Prompt 体系变更 | 模板结构、调用策略、PromptBuilder 逻辑 |
| 全局命名变更 | 模块名、函数名、文件名重命名 |
| 架构重构 | 跨模块的代码重组 |

### ADR 文档格式

```
DEC-XXX: 决策标题
- 背景：为什么需要变更
- 决策：变更内容
- 影响范围：涉及的模块、表、接口
- 替代方案：考虑过但未采纳的方案
- 验证方案：如何验证变更正确性
- 回滚方案：出问题如何回滚
```

### Chapter 8: 产品设计红线 — 双语言全局强制约束（对应原指令"一"）

#### 8.1 母语 + 目标语言初始化逻辑（全局统一）
1. 用户首次登录初始化流程（Stage2 新用户引导）**强制增加双语言选择项**：母语、目标学习语言，两项为必填项，不可跳过；
2. 全局所有按钮、弹窗提示、页面文案、系统引导、AI 伴读对话文案，**全部跟随用户绑定母语渲染展示**，禁止固定单一语言、多语言混乱展示；
3. 全系统仅唯一修改入口：个人中心专属语言设置面板，**所有页面、游戏、AI 对话、学习模块禁止额外弹出语言选择弹窗 / 切换控件**；
4. 删除全项目内所有分散、无生效逻辑的语言选择控件、弹窗、切换按钮；仅保留个人中心统一语言修改入口；
5. 数据联动：个人中心修改母语 / 目标语言后，实时同步 user 主库（user_profiles / User 表对应字段），全平台实时刷新语言配置，无需重启登录。

#### 8.2 全学习 / 游戏 / AI 模块语言绑定校验
1. 30 天 AI 学习计划、每日五阶段学习全流程：词汇、例句、学习提示匹配目标语言，界面提示匹配母语；
2. 游戏模块（词语接龙、听音辨词、语法填空等）：题干、选项、引导弹窗、结算文案双语言绑定；
3. AI Companion 伴读、口语对话、AI 总结、AI 生成素材：输出素材=目标语言，对话话术/鼓励/界面提示=母语；
4. 错题本、学习报表、定级测试、词汇库：内容语言=目标语言，UI 展示=母语；
5. 任何语言不匹配、多语言混杂、切换不生效 → 判定 P0 阻塞缺陷，优先修复。

### Appendix E: AI Gateway 实现细则 — 双语言入参 & 权限合规（对应原指令"二"）

1. 混元模型全链路绑定宪法约束框架，所有 AI 调用统一走唯一 AI Gateway / aiService 入口，禁止直连模型、前端私发 prompt；
2. 每次 AI 请求必须携带 `userId`、`nativeLang`（母语）、`targetLang`（目标语言）三个固定参数；网关校验参数完整才发起调用，缺失直接拦截并返回标准错误码；
3. AI 分层权限管控：
   - 输出内容严格限定在用户目标语言范围内，禁止跨语言乱生成；
   - 伴读 / 学习计划生成 / 游戏题库生成 / 口语对话四类场景分模块权限，网关配置场景白名单，禁止跨业务生成无关内容；
   - 严格遵循 30 天学习计划、每日五阶段固定结构，AI 不得自定义学习时长、阶段顺序、每日词汇数量；
4. 混元接入全功能激活：补齐缓存匹配（按双语言参数生成独立 cacheKey，语言隔离）、计费日志与 tokens 消耗记录（ai_call_logs 完整记录母语/目标语言）、降级与重试规则（超时/限流返回母语兜底提示）；
5. 全项目 AI 点位逐行审查：学习计划生成、AI 口语、伴读对话、游戏题库、写作批改、翻译模块，全部补充双语言入参，缺失参数接口统一重构。

2. **onboarding 强制跳转**：未完成双语言配置（native/target 任一为空）的用户，直接访问任何内部业务页面（chat/learn/game/profile 等）时，**必须强制重定向回引导页**，禁止加载业务内容；前端路由守卫 + 后端接口双重拦截。

1. **前端缓存机制**：静态资源必须带版本号 / hash 后缀（如 `app.js?v=hash`），nginx 对 HTML 入口配置 `Cache-Control: no-cache`；部署后必须强制刷新用户侧缓存，杜绝旧页面残留。

### Appendix C：生产运维强制规范

#### C.1 数据库变更
1. **Expand-Contract 三阶段分步骤迁移**（破坏性变更强制）：① 扩展兼容双字段 → ② 业务全量适配新字段 → ③ 下线旧字段；每阶段独立迁移文件，可单独部署、单独回滚，禁止单步不可逆破坏性变更。
2. 生产环境 Schema 变更统一使用 `prisma migrate deploy`，迁移文件必须入仓留痕（`_prisma_migrations` 保留版本记录）；**生产环境永久禁止 `prisma db push`**。
   - *衔接说明*：非破坏性加性变更（新增可选列/新增表/新增索引）仍走 `migrate deploy` 单迁移文件即可，无需三阶段；三阶段仅对破坏性变更强制。

#### C.2 部署流程
1. 强制使用标准化**幂等部署脚本 `deploy/deploy.sh`**，内置五步固定流程：数据库备份 → 代码拉取 → 迁移校验 → 服务重启 → 健康检查；脚本必须入仓版本化管理，不含服务器凭据。
2. 禁止现场临时手写脚本部署，禁止跳过备份、跳过校验步骤。
3. **双目录强制同步**：后端代码与静态页目录必须同步更新，禁止只更后端不更前端导致整改不生效。

#### C.3 备份规则
1. 所有生产变更前必须执行全量数据库备份（`pg_dump`），备份文件独立留存。
2. 每季度必须执行一次备份恢复演练，验证备份可恢复性，验证结果入账簿归档。

### Appendix D：系统配置与权限治理规范

1. `SystemConfig` 表**禁止无审批直插数据库**，所有配置变更必须走管理员后台 + 审批台账流程；DB 层增加 UPDATE 触发器记录操作人/时间/新旧值。
2. 管理员权限配置必须登记操作人、用途、有效期，禁止无主权限长期遗留。
3. 限流白名单、测试账号等敏感配置全部通过**环境变量注入**，禁止硬编码到公开仓库代码。

### Appendix E 增补：商业与成本管控规范

1. **OCR 拍照翻译分层限流**：单用户每日免费识别上限 **50 张**；全局设置单日成本阈值，到达阈值自动熔断免费入口（返回 `OCR_COST_LIMIT`），引导开通套餐。
2. 所有付费 / 免费功能必须接入统一计费框架；**时长/额度扣减失败直接拦截服务，禁止先使用后扣费**。

### Appendix F：测试验收强制规范

1. 所有上线变更必须完成**线上网页版全页面预览验收**，留存 PC 端 + 移动端多端截图证据（入账簿附件）。
2. 核心功能验收必须覆盖三类场景：**新用户全链路 / 存量用户兼容性 / 异常降级逻辑**，缺一项不予通过。

### 验收一票否决增补（并入 Chapter 4 DoD）
1. 线上网页版无完整预览验收记录 → 翻译模块驳回；
2. OCR 拍照翻译无用户/全局成本限流熔断 → 不予冻结；
3. 部署无标准化幂等脚本 → 迭代上线暂停；
4. SystemConfig 直插数据库、无权限审计 → 所有配置相关功能打回；
5. 数据库采用单步不可逆迁移或生产使用 `db push` → 禁止发布生产。

## 附录 C.5 生产部署验收三原则（2026-07-26 紧急处置修订）

针对「账簿闭环、线上失效」的虚假交付风险，所有生产部署（含 Stage 11 后续子模块）必须**同时满足以下三项**方算完成，缺一不可；禁止以「脚本执行成功」「后端重启成功」代替全链路验收：

1. **服务健康**：后端服务重启成功，`GET /api/health` 返回 200，部署日志无未处理报错；
2. **前端全量同步**：前端静态资源经「双目录一致性校验」与仓库源码（同 commit）逐文件比对一致（`cmp` 零差异），版本号（`?v=`）与文件内容均一致；不一致即部署失败并告警（脚本 `deploy.sh` 步骤 5.5 已实现，失败 `exit 1`）；
3. **用户侧实测**：核心功能点线上实测算验通过，普通用户（无需强制刷新）访问即见最新页面与预期行为——含语言控件清理、全局语言切换生效、新功能可见、onboarding 强制跳转等。

### C.5.1 双目录一致性校验（强制）
- 前端源码与后端同仓（SOURCE_DIR=仓库根），部署目标 `/www/xuewaiyu`；
- 校验覆盖：仓库根 `*.html` + `assets/` + `public/`，逐文件 `cmp`，缺失/差异即失败告警（邮件：`DEPLOY_ALERT_MAIL`，默认 root）；
- 该步骤固化于 `deploy/deploy.sh` step 5.5（commit 4b03381）。

### C.5.2 限流白名单环境变量注入
- `pm2 restart --update-env` 不复源 `.env.production`；白名单必须显式 `pm2 set xuewaiyu-backend:RATE_LIMIT_WHITELIST` 注入（已固化于 deploy.sh step4，幂等）。

### C.5.3 已知禁改红线（重申）
