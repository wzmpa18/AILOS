## 二、分阶段结果

### 阶段一：计费一致性（6/6 PASS）

核心发现：
- **DEF-P3-01 (P0)**：缺少幂等防护，同一 requestId 可重复扣减 → 新增 `requestId` 唯一约束 + consume 幂等查重
- **DEF-P3-03 (P0)**：购买套餐单位分钟 → 消费按秒 → 余额显示 60 倍差异（1小时包显示约 1 分钟可用） → `minutesTotal` 统一为秒
- **DEF-P3-04 (P0)**：`deploy.sh` 未注入 `.env.production` → `prisma migrate deploy` 历史上从未成功 → 修复后首次全自动迁移
- **DEF-P3-02 (P1)**：缺少退款时长回退 → 新增 `refundOrder` + 管理端路由 `POST /api/admin/orders/:id/refund`

### 阶段二：风控规则（4/4 PASS）

四道防线全部验证：设备终身试用一次 (DEVICE_TRIAL_CLAIMED) → IP 前缀日频控 (5/天, 无指纹兜底) → 同 /24 轮换无法绕过 → 设备账号绑定上限 (2)。

### 阶段三：用户账号（4/4 PASS）

并发登录无 P2002 (8×200, 8 互异 token)、禁用即锁 (401)、密码重置双向验证 (旧码 401/新码 200)、过期 Token 正确拦截 (401)。

### 阶段四：管理后台权限（3/3 PASS）

6 个 admin 端点全 403 (普通用户)、无 token 访问全 401、adjust/disable/refund 不传 opPassword 全 403 (二次校验独立于前端弹窗)。

### 阶段五：系统容错（3/3 PASS）

Redis 宕机 fail-open (登录/计费/风控零崩溃)、DB 事务原子回滚 (模拟异常无残留)、AI 异常不 500/不白屏。
