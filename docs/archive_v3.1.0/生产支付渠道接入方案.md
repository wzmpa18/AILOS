# 生产支付渠道接入方案

> 关联：第三阶段收尾项 3(2)。本方案目标——生产支付切换**仅改配置 + notify 验签薄层**，业务代码零改动。
> 唯一到账入口：`POST /api/billing/payment/callback` → `confirmPaymentOrder`（状态机幂等）。

## 1. 现状（沙箱/联调）

- 支付下单：`POST /api/billing/payment/create` → 生成 `translationPackageOrder`（status=pending）。
- 支付回调：`POST /api/billing/payment/callback` → `confirmPaymentOrder(orderNo, ...)`：
  - 按 `orderNo` 查单；已 paid 直接 409 幂等返回；
  - 校验金额/状态后置 `status=paid`、写入 `paidAt`、发放 `TranslationPackageOrder` 时长（`minutesTotal/minutesUsed`）；
  - 全程在事务内，超量/重复自动拒绝。
- 当前 `PAY_PROVIDER` 指向沙箱（如 `sandbox`），回调来自测试商户。

## 2. 切换生产所需配置项（仅 env，不改代码）

| 配置项 | 说明 | 取值来源 |
|--------|------|----------|
| `PAY_PROVIDER` | 支付渠道标识 | `production`（沙箱为 `sandbox`） |
| `PAY_MCH_ID` | 生产商户号 | 微信/支付宝商户平台 |
| `PAY_API_KEY` | 生产 API 密钥（签名用） | 商户平台证书/密钥 |
| `PAY_NOTIFY_URL` | 生产异步回调地址（公网可达） | `https://yandao.vip/api/billing/payment/callback` |
| `PAY_CERT_PATH` / `PAY_CERT_SERIAL` | 生产证书路径/序列号（若渠道需要） | 证书文件部署于服务器安全目录 |
| `PAY_WEBHOOK_SECRET` | 回调验签共享密钥 | 与渠道后台一致 |

> 以上均通过 `ecosystem.config.js` / `.env.production` 注入 PM2，**不写死在源码**。

## 3. 验签逻辑（薄层，独立中间件）

- `src/server/middleware/paymentVerify.js`（新增，轻量）：
  - 读取渠道原始报文 + `signature`/`nonce`/`timestamp`；
  - 用 `PAY_API_KEY`/`PAY_WEBHOOK_SECRET` 按渠道规则重组待签串并 HMAC-SHA256；
  - 验签失败 → `401 INVALID_SIGN`；时间戳超时（±5min）→ `401 EXPIRED`；
  - 验签通过 → `next()`，业务仍走既有 `confirmPaymentOrder` 幂等状态机。
- 业务层**不感知**沙箱/生产差异，仅消费"已验签 + 已解析"的订单参数。

## 4. 切换步骤（生产发布 runbook）

1. 在商户平台配置生产 `PAY_NOTIFY_URL` = `https://yandao.vip/api/billing/payment/callback`；
2. 将生产证书/密钥放入服务器安全目录，权限 `600`，仅 pm2 用户可读；
3. 修改 `.env.production`：`PAY_PROVIDER=production` + 生产商户号/密钥/证书；
4. `pm2 set` 注入或直接 `pm2 restart xuewaiyu-backend`（不重新部署代码）；
5. 用渠道"下单→支付→回调"沙箱/生产灰度单笔，核对 `translationPackageOrder.status=paid` 与 `paidAt` 写入、时长发放；
6. 观测 `/api/billing/status` 与 `/api/billing/admin/orders/export` 对账一致。

## 5. 约束与回滚

- **业务零改动**：切换仅涉及 env + 验签中间件配置，无需改 `confirmPaymentOrder` 逻辑（满足纪律"切换生产仅需修改配置、无需改动业务代码"）。
- 若生产回调异常：将 `PAY_PROVIDER` 切回 `sandbox` 并重启 pm2 即可回退，不触达业务代码。
- 金额/状态一致性由既有 `confirmPaymentOrder` 事务 + 幂等 409 保证，生产切换不引入新风险。

## 6. 验收证据

- 沙箱端到端（此前验收）：下单→支付→回调→`status=paid`→时长发放→导出可见，全绿。
- 生产切换后：单笔灰度 + 对账导出一致即可宣布生产支付生效。
