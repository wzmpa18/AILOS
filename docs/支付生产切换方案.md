# 支付链路生产切换方案（沙箱 → 真实支付渠道）

> 第三优先级 Task5 交付物。目标：切换生产**仅需修改配置与新增验签适配层，业务代码零改动**。

## 1. 当前沙箱架构（已上线）

```
前端 billing.html
  └─ POST /api/billing/payment/create      下单（status=pending，不到账）
       └─ 返回 paymentUrl（沙箱收银台弹窗）
  └─ 用户"支付"（沙箱模拟成功/失败双分支）
       └─ POST /api/billing/payment/callback  { orderNo, result }
            └─ billingService.confirmPaymentOrder(orderNo, {...})
                 ├─ pending→paid：权益原子到账（按量包/订阅事务写入）
                 └─ pending→failed：标记失败
  └─ GET /api/billing/payment/status/:orderNo  订单状态轮询
```

关键设计：**到账唯一入口是 `confirmPaymentOrder`**（幂等：非 pending 一律 409），
真实网关与沙箱共用该方法，这是"业务代码零改动"的保障。

## 2. 生产切换步骤

### 2.1 配置项（新增环境变量，`.env.production`）

| 变量 | 说明 | 沙箱值 | 生产值 |
|---|---|---|---|
| `PAYMENT_PROVIDER` | 支付渠道 | `sandbox` | `wxpay` / `alipay` |
| `PAYMENT_MCH_ID` | 商户号 | - | 渠道商户号 |
| `PAYMENT_API_KEY` | API 密钥（v3） | - | 渠道密钥 |
| `PAYMENT_NOTIFY_URL` | 异步回调地址 | - | `https://yandao.vip/api/billing/payment/notify` |
| `PAYMENT_CERT_PATH` | 平台证书路径 | - | 服务器证书目录 |

### 2.2 接入点 A：下单（`createPaymentOrder` 返回值替换）

- `PAYMENT_PROVIDER=sandbox`：返回 `/api/billing/payment/sandbox/:orderNo`（现状）。
- 生产：调用渠道「统一下单」API（金额取 `PACKAGE_CATALOG` 服务端真值 `priceCny`，
  订单号沿用 `orderNo`），将返回的 `prepay_id`/收银台 URL 填入 `paymentUrl` 字段。
  前端无需任何修改（它只消费 `paymentUrl`）。

### 2.3 接入点 B：回调验签（新增薄适配层，唯一新增代码）

新增路由 `POST /api/billing/payment/notify`（**免登录**，渠道服务器直调）：

```js
// 伪代码——验签通过后调用与沙箱完全相同的 confirm 方法
router.post('/payment/notify', rawBody, async (req, res) => {
  const event = await provider.verifySignature(req);   // 渠道 SDK 验签（防伪造）
  if (!event.valid) return res.status(401).end();
  await billing.confirmPaymentOrder(event.orderNo, {
    paymentId: event.transactionId,
    result: event.tradeState === 'SUCCESS' ? 'success' : 'failed',
  });   // 幂等：重复通知 → 409 被吞掉，按渠道要求返回成功应答
  res.json({ code: 'SUCCESS' });
});
```

同时：沙箱回调接口 `POST /api/billing/payment/callback` 在
`PAYMENT_PROVIDER !== 'sandbox'` 时直接返回 403（禁用手动确认通道）。

### 2.4 安全与对账

- 金额校验：回调中比对渠道回传金额 == 订单 `priceCny`，不一致拒绝入账并告警；
- 幂等：`confirmPaymentOrder` 以订单状态机保证（非 pending 一律 409），渠道重试安全；
- 对账：管理员接口 `GET /api/billing/admin/orders/export?granularity=day|month&date=...&format=csv`
  导出订单明细与汇总（状态计数/总金额/总时长），与渠道账单按 `orderNo` 逐笔核对；
- 证书轮转：平台证书由渠道 SDK 自动拉取，密钥仅存服务器环境变量（不入仓）。

### 2.5 切换演练清单

1. `.env.production` 填入渠道配置，`PAYMENT_PROVIDER=wxpay`；
2. 部署（标准 `deploy.sh`，两道自检闸门）；
3. 1 分钱真实支付验证：下单 → 扫码支付 → notify 验签入账 → `payment/status` = paid → 余额到账；
4. 对账导出比对当日渠道账单；
5. 验证 `payment/callback`（沙箱通道）返回 403。
